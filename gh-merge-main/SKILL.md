# Pull Requestをmainへマージ

既存のPull Requestを、GitHub CLIの`gh`で既定ブランチへマージし、作業ブランチを削除する。実装、commit、push、PR作成は担当しない。

## 出力言語

- ユーザーが別の言語を明示しない限り、日本語で出力する。
- 状態確認、停止理由、実行結果を日本語で報告する。
- コマンド、パス、API、識別子、製品・サービスの正式名称は、正確性のため必要な原表記を維持する。

## 実行前の条件

- ユーザーが、対象Pull Requestのマージと作業ブランチ削除を明示的に依頼していることを確認する。不明な場合は、PR番号またはURLと削除の可否を確認して停止する。
- `gh --version`と`gh auth status`でGitHub CLIと認証を確認する。利用できない場合は`gh auth login`を案内して停止する。
- PR番号またはURLが指定されていればそれを使う。指定がなければ、現在のブランチに対応するPRだけを`gh pr view`で特定する。複数候補から推測しない。
- `gh repo view --json defaultBranchRef`で既定ブランチを確認する。ユーザーが`main`を指定した場合は、既定ブランチが`main`であることを確認する。

## マージ前の確認

次を読み取りで確認する。

1. `gh pr view`でPRがOpenかつReadyであり、baseが既定ブランチ、headが既定ブランチ以外であることを確認する。
2. PRのhead commit SHA、マージ可能性、競合、レビュー状態を確認する。
3. `gh pr checks --required`で必須チェックがすべて成功していることを確認する。必須チェックがない場合は、その事実を記録する。
4. リポジトリの必須レビューまたはマージキューがある場合は、その要件を満たしていることを確認する。未承認、保留、失敗、競合、不明な状態を成功扱いしない。
5. `git status --short`でローカル作業ツリーが空であることを確認する。未保存変更がある場合は、削除による損失を避けるため停止する。
6. `gh repo view`で選ぶマージ方式が許可されていることを確認する。ユーザー指定がなければ、squash mergeを優先する。

## マージとブランチ削除

1. 確認済みのhead commit SHAを`--match-head-commit`へ指定する。
2. 許可された方式で、次の形のコマンドを実行する。

   ```bash
   gh pr merge <PR> --squash --delete-branch --match-head-commit <HEAD_SHA>
   ```

3. マージキューを使うリポジトリでは、`gh pr merge --delete-branch`の標準動作に従う。キュー投入が即時マージではない場合は、マージ済みと報告せず、状態を報告して停止する。
4. `--admin`、force push、保護規則の回避、既定ブランチの削除は行わない。

## マージ後の確認

- `gh pr view`でPRがMergedであり、マージcommitと時刻を確認する。
- ローカルの既定ブランチへ切り替え、`git pull --ff-only`でリモートの`main`を反映する。
- `git branch --list <head>`と`git ls-remote --heads origin <head>`で、ローカル・リモート双方の作業ブランチが削除されたことを確認する。
- Pull Request URL、マージcommit、削除したブランチ、実行したチェック結果を簡潔に報告する。

## 停止条件

次の場合はマージ・削除を行わず、確認結果と必要な対応を報告する。

- 対象PR、base、head、またはユーザー承認が曖昧
- 必須チェック、レビュー、競合、マージキューが未完了
- ローカル作業ツリーに変更がある
- 既定ブランチ以外へのマージ、または許可されていない方式が必要
- `gh`の認証またはGitHub権限が不足
